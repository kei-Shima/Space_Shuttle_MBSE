1. 目的

本パッケージの図を、NASA-HDBK-1009A の考え方にならって、行＝NASA の SE の技術プロセス、列＝SysML の4つの柱のグリッドに入れて、どのプロセスのどの柱の図が多く、どこが空いているかを示す。あわせて、INCOSE の MBSE の取り組み（Estefan 2008 の手法の調査）に出る手法（Harmony-SE・OOSEM・Vitech・JPL State Analysis）の工程と本パッケージの文書・図の対応を判定し、SEBoK の Architecture Frameworks の考え方（枠組みはビューを整理し、不足の検出を助ける）に沿って、ISO/IEC/IEEE 42010 の概念と SSD-VPT-SYS-001 の要素の対応を示す。グリッドは SSD-VPT-SYS-001 のビュー（関心事で区切る）とは別の切り口で、SE のプロセスと柱で区切る。次の版（モデル計画書）の入力にもなる。

2. 範囲と規則

対象は本版までの全図（272図）。行・列の割り当ては本書の判断で、規則は結果を見る前に決め（PLAN_CS）、結果を見てから直した点は PLAN_CS の追記に残した。図はちょうど1つのセルに入る（複数に数えない）。列は図の題名の語で、行はビューポイント（VP）から決め、題名の語で上書きする（下の2つの表）。HDBK-1009A のグリッドは技術プロセス 1〜9 だけなので、技術管理プロセス 10〜17 の行と「その他」の列は本書が足した（拡張）。手法の対応は自己採点で、判定は SSD-MBS-SYS-001 と同じ規則（有・一部・無）。Estefan 2008 は再利用の条件が書かれていないので本文を写さず、工程名を言い換えた。

3. グリッドの出典

NASA-HDBK-1009A §4.3.3：グリッドは、行に NASA の SE の技術プロセス、列に SysML の4つの柱をとる。HDBK のグリッドは技術プロセス 1〜9 だけで、技術管理プロセス 10〜17 を含まない。（出典は参考文献の頁）

10. 読み方と弱いところ

図が0の行は 製品の実装・製品の統合・製品の妥当性確認。SSD-MBS-SYS-001 の判定（実装・統合・妥当性確認の図表が無い）と照らして読む。ただし割り当ては粗い（たとえば区画の配置図は設計解の定義に入れた）ので、0 は欠けの目安で、断定ではない。決定分析の行に入る図は少ない（図104 のトレードスタディ）。手法の対応で判定が「一部」のものは、ステークホルダーのニーズの分析・候補アーキテクチャの比較・妥当性確認である（MBS-10〜14）。グリッドは図を足すたびに古くなるので、図を足す版は作り直す。
