1. 目的

天候の限界（横風・雲高・視程・雷雨・降水・雷までの距離・温度など）を、制約の定義（constraint def）として持つ。DE（SSD-WXC-ORB-001）は限界の値を件数・値の表で持ったが、『観測値が限界に対してどういう関係にあるか』を式として持つ形は無かった。本書は DE の記録を、不等式だけの制約と、その限界の値（版・条件つき）に並べ替える。**観測値・飛行の値には束ねない**（束ねると判定になる）。図312〜314 の図312 は制約ブロックを描いたパラメトリック図。

2. 範囲と書き方

制約は 87（飛行規則 32・2010 の雷 55）、限界の値は 168件。DE の数える記録 191件のうち、比較が『その他』の 2件と、適用の期間・待ち時間の 21件（別の表）を除く 168件がちょうど1つの制約に属する。値・単位・条件・根拠は DE の記録（WXC-nnn）のまま（換算しない）。式は上限・下限・帯の不等式だけ（帯は許す帯と禁じる帯）で、原子の限界どうしの論理（and／or／unless）と端点の含み方（≦か＜か）は形式化しない。新しい抽出は無く、制約の数は DE の記録から決まっている（設計の版）。

注記　範囲・取れなかった値・本書の判断：式は不等式だけ：許す側の上限＝`observedValue <= limitValue`、下限＝`observedValue >= limitValue`、許す帯＝`observedValue >= limitLo and observedValue <= limitHi`、**禁じる帯＝`observedValue < limitLo or observedValue > limitHi`**（範囲の制約 12：禁じる帯 10・許す帯 2）。限界の値は `part def WeatherLimit` の使用（168件）で、`constraintId` 属性で制約を指す。**観測値・飛行の値への `bind`・`assert constraint`・`:=` は書かない**（束ねると『超えた・超えない』の結果になり、DC の着陸の記録・DD の LCC 違反の記録に判定が付く。方針の変更になるので、ユーザーの決定が要る）。**限界の向き（事後の直し）**：DE の 2010 の記録は、『飛行を許す側』の向きで付けたとされたが、禁じる帯（雷雲からの距離の帯など。観測値が帯の中なら禁じる）と、適用の期間・待ち時間（単位が分・時間。観測値の限界でなく『何分間・何時間』）が混じっていた。規則 ID の表で付け直し（PLAN_DH 追記2）、適用の期間・待ち時間 21件は制約にせず（表に別に示す）、禁じる帯は不等式を逆にした。端点を含むか（≦か＜か）は形式化していない（本文が『greater than or equal to 1500 V/m』で禁じるものは許す側が `< 1500` だが、式は `<=` と書く）。
注記　範囲・取れなかった値・本書の判断：条件（昼夜・滑走路・機体の状態・システムの故障）は限界の属性に残し、制約の名前に入れない。同じ制約に条件違いの限界が複数あるときは、すべて並べた（版ごと）。2010 は『打上げ』の規則で、飛行規則の着陸の規則と場面が違う。各版はその時代の基準で、他の時期の飛行には当てはめない。2010 は連邦レンジ・FAA の雷の基準で、シャトル固有の LCC ではない。
注記　範囲・取れなかった値・本書の判断：項目または場面が『その他』の制約 35件（飛行規則 8・2010 27）は、DE の統制語彙の外の限界で、本文の語が違う複数の文脈（DTO・ドラッグシュート・ECAL/ELS・待ち時間・雲からの距離など）を1つの名前にまとめている。文脈の区別は限界の属性（条件）にあり、制約の名前では区別できない（例：WXK-006 WxCrosswindOtherMax、限界 11件）。
