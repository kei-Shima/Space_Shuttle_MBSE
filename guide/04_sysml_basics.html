4　SysML を読む

SysML v2 のテキストを書けるようになる必要はありません。「何が書いてあるか」を読めれば十分です。実物の 5 か所を取り上げます。

引用について：以下のコードは、このパッケージの SysML/ から原文のまま抜いたものです（出典の行番号つき）。

読み方の基本

  • X def Y { … } は「Y という型を定義する」。X は種類（requirement、part、state など）。
  • doc /* … */ は説明文（日本語の注釈）。まずここだけ読めば内容がつかめます。
  • // … はコメント。

例1　要求（requirement def）

REQ-SYS-01 の値を数にしたものです。require constraint が「満たすべき式」です。

    requirement def <'REQ-SYS-01'> ReqSys01 {
        doc /* REQ-SYS-01 の値の形式化（数） */
        attribute majorElements : Integer { doc /* RF-001 主要素の数（単位なし） */ }
        attribute srbCount : Integer { doc /* RF-002 SRB の本数（単位なし） */ }
        attribute ssmeCount : Integer { doc /* RF-003 SSME の基数（単位なし） */ }
        require constraint { doc /* ＝ 4 */ majorElements == 4 }
        require constraint { doc /* ＝ 2 */ srbCount == 2 }
        require constraint { doc /* ＝ 3 */ ssmeCount == 3 }
    }
    #refinement dependency <'REQ-SYS-01>RQM'> from ReqSys01 to SSD_RQM_SYS_001::REQ_SYS::REQ_SYS_01;

出典：SSD-RQF-SYS-001.sysml（12〜21 行目）

読み解き：doc の「主要素の数」は 4、SRB は 2 本、SSME は 3 基と書いてあります。最後の #refinement dependency は、要求の文面側（RQM）とのつながりです。

例2　検証ケース（verification def）

    verification def <'VC-REQ-SYS-01'> VC_REQ_SYS_01 {
        doc /* REQ-SYS-01 をI（検査）で確かめる。 */
        @VerificationMethod { kind = VerificationMethodKind::inspect; }
        subject s : Parts::Part;
        objective { verify REQ_SYS::REQ_SYS_01; }
        return verdict : VerdictKind;
    }

出典：SSD-VER-SYS-001.sysml（8〜14 行目）

読み解き：objective { verify … } が「どの要求を確かめるか」。kind = inspect が方法（検査）。return verdict が結果（合否）です。

例3　状態（state def）

        entry; then PH_1;
        state PH_1 { doc /* PH-1 打上げ前 */ }
        state PH_2 {
            doc /* PH-2 上昇 */
            entry; then PH_2a;
            state PH_2a { doc /* PH-2a 上昇・第1段 */ }
            state PH_2b { doc /* PH-2b 上昇・第2段 */ }
            state PH_2c { doc /* PH-2c 上昇・軌道投入 */ }
            transition TR_02 first PH_2a accept SrbSeparation then PH_2b;
            transition TR_03 first PH_2b accept MecoEtSeparation then PH_2c;
        }

出典：SSD-BEH-ORB-001.sysml（38〜48 行目）

読み解き：state PH_2 の中に PH_2a〜PH_2c の状態があり、transition は「SrbSeparation を受けたら PH_2a から PH_2b へ」という切り替えです。図76と見比べてください。

例4　ポート（port def）

    port def CryoO2Port :> FluidPort { out item :>> fluid : CryoO2; }

出典：SSD-IBD-ORB-001.sysml（18〜18 行目）

読み解き：CryoO2Port は、極低温酸素を出す口という型です。部品どうしをつなぐ線は、このポートの間に引かれます。

例5　満たす関係（satisfy）

        satisfy InterfaceRequirements::IRQ_ALS_01 by context.sts.orb.eclss.IF_ALS_01 { doc /* 割付先：IF-ALS-01 */ }
        satisfy InterfaceRequirements::IRQ_ALS_02 by context.IF_ALS_02 { doc /* 割付先：IF-ALS-02 */ }

出典：SSD-IRQ-ECL-001.sysml（2691〜2692 行目）

読み解き：satisfy A by B は「要求 A を B が満たす」という線です。ここではインタフェース要求 IRQ-ALS-01 を、IF-ALS-01 が満たします。doc に「割付先：…」とあります。

VS Code で開く

VS Code に SysML v2 の拡張機能を入れると、構文の色分けと検査ができます。推奨の拡張機能は、リポジトリの .vscode/ に入っています。くわしくは README の「SysML v2 モデルを VS Code で開く」の節を見てください。
