## 1. 目的

上位の IF（システム間の IF-SYS-01〜10 と、オービタの系どうし・外部要素の IF-ORB-01〜49）のそれぞれに、インタフェース要求を1件ずつ定める。要求は IF 特性表（SSD-ICD-ORB-001：流れるもの・特性値・冗長・フェーズ）から起こし、上位の要求（L1：SSD-REQ-SYS-001、L2：SSD-REQ-<系>-001）から導出し、IF を割付先にし、検証の根拠（飛行・試験の記録）を付ける。これまで要求は主に機能行に割り付けていて、IF を割付先にした要求は 589件のうち 39件だった。

## 2. 書き方

要求の ID は IF の番号に合わせる（IF-ORB-05 → IRQ-ORB-05）。要求文は「送り側は受け側へ、流れるものを、特性値・条件で供給する（伝える・支える）こと」の形で、値と単位は IF 特性表と資料のまま書いた。上位は、その IF が支える既存の要求である。検証方法は A（解析）・T（試験）・I（検査）・D（実証）、検証の状態は、検証方法に合う一次資料の記録があるものを「根拠あり」、見つからなかったものを「根拠なし」（理由つき）とした。設計の記述をなぞるだけの文は根拠にしていない。

> **注記** インタフェース要求・導出・充足・検証は、本書と SysML のパッケージ SSD_IRQ_SYS_001 に置いた。要求モデル（SSD-RQM-SYS-001）と検証定義書（SSD-VER-SYS-001）の件数は変えていない。

> **注記** トレース網羅書（SSD-TRC-SYS-001）では、インタフェース要求を、IF を所有する系の要求として数えた（導出・割付・検証の指標 C1〜C3 と、IF の要求の指標 C5）。

> **注記** 検証の根拠には、IF そのものの計測の記録ではなく、その IF を含む系が飛行で公称に働いたという Mission Report の記述や、不具合の記録（IF が働いていたことを間接に示すもの）で支えたものがある。特性値そのものを確かめた記録ではないので、根拠の強さは要求ごとに違う（本書の判断）。

> **注記** 検証の根拠が見つからなかった要求：IRQ-ORB-28（IF-ORB-28）。Rev. CB で Mission Report 133冊（STS-1〜135）などを探し直した。オービタから SRB への給電は STS-9（仕様内）と STS-82（31.12 V）で確かめられたが、STS-69 の打上げ試行で右 SRB の B 母線の地上測定が 32.04 V と要求の上限 32 V を超え（免除された）、記録が混在する。3系統の構成とバックアップの記録も無い。

> **注記** 検証の根拠の調査（Rev.
