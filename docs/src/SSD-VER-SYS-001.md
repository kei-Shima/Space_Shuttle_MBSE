## 1. 目的

要求（SSD-REQ-SYS-001 と L2 の要求書18件）ごとに検証ケースを置き、検証方法・検証の対象（主体）・判定を示す。要求書の検証（V&V）の表で示した検証の根拠を、SysML v2 の検証ケース（verification）と verify の関係にし、要求モデル（SSD-RQM-SYS-001）と構造モデルにつなぐ。要求書 × 検証方法・判定の集計は 図110 検証マトリクス に示す。

## 2. 書き方

要求書の欄と SysML v2 の要素の対応を示す。判定の pass は、公開資料の飛行の実績・解析・検査の記録で要求が満たされたことを確かめたもので、検証を新たに行ったものではない。

| 要求書の欄 | SysML v2 の要素 |
|---|---|
| 要求1件 | verification def 1つ（短い名前は VC-要求の ID） |
| 要求書の検証の欄（A・T・I・D） | metadata VerificationMethod（標準ライブラリ。A＝analyze、T＝test、I＝inspect、D＝demo） |
| 検証する要求 | objective の verify（要求モデルの requirement） |
| 検証の対象 | subject（定義では Parts::Part、結果では要求を充足する最初の部品・インタフェースに結び付ける） |
| 検証の根拠の状態 | 結果の verdict（根拠あり＝pass、根拠なし＝inconclusive） |

## 9. 注記（出典間の相違・構成変更）

> **注記** 判定は、要求書の検証の根拠（公開資料の頁）による。pass は「公開資料の記録で満たされたことを確かめられる」の意味で、本書が試験・解析を行ったものではない。

> **注記** 主体は、要求を充足する部品・インタフェースのうち要求モデルの satisfy の最初のものである。要求が複数の部品で充足されるときも、検証ケースの主体は1つにした。

> **注記** 検証方法は要求書の想定する方法で、一次資料の検証計画（例：NSTS 07700 の検証要求）によるものではない。

> **注記** 検証の判定を含むトレースの連鎖の網羅と切れ目は [SSD-TRC-SYS-001](SSD-TRC-SYS-001.md) に示す（SysML v2 テキスト：model/SSD-TRC-SYS-001.sysml）。
