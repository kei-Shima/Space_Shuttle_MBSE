## 1. 目的

オービタとスタックの運用で、乗員・機体またはミッションの喪失に至りうる危険な状態（ハザード）を上から挙げ、それぞれの原因、原因を抑える管理策（設計・警報・手順・飛行規則など）、管理策の要求の検証の判定までを1つの連鎖として示す。故障解析表（SSD-FMEA-*）の下からの解析に対する、上からの解析である。全体は図120・121 に示す。

## 2. 書き方

ハザード・原因・管理策と重大度は一次資料（SCOM・運用飛行規則・IOA・Mission Report）の頁と照合語で示す。原因に関わる機能説明書、管理策が当たる既存の要求・警報・飛行規則・活動図は、設計パッケージの ID で示した。起こりやすさは資料に無いので、本書がハザードに関わる系の冗長の段階（SSD-FMEA-ORB-001 §4）から推定した（最も弱い段階が 2故障許容 → 低、1故障許容 → 中、0故障許容・冗長なし → 高）。リスクは重大度（影響）と起こりやすさの組で、SysML v2 では標準ライブラリの RiskMetadata の Risk（RiskLevel の probability・impact）で示す。

## 3. 重大度と起こりやすさ

重大度と起こりやすさの区分と、RiskMetadata の Level（LevelEnum）への対応を示す。

| 区分 | 定義 | Level |
|---|---|---|
| 破局的 | 乗員・機体の喪失に至る | high |
| 重大 | ミッションの喪失・機体の重大な損傷・乗員の負傷に至る | medium |
| 軽微 | ミッションの一部の喪失・軽い損傷 | low |
| 起こりやすさ 低 | 関わる系がすべて 2故障許容 | low |
| 起こりやすさ 中 | 関わる系の最も弱い段階が 1故障許容 | medium |
| 起こりやすさ 高 | 関わる系に 0故障許容・冗長なし（受動）がある | high |
